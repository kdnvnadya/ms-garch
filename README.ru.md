# Markov-Switching GARCH для моделирования волатильности в кризисные периоды

English version: [README.md](README.md)

Дипломная работа (ВКР): моделирование волатильности финансовых активов в кризисные периоды с помощью Markov-Switching GARCH. В отличие от обычного GARCH, здесь сама волатильность может переключаться между скрытыми режимами ("спокойный" / "кризисный"), и модель находит эти режимы по данным, а не по заранее заданным датам.

## Зачем два актива

Работа проверяет один и тот же метод на двух совсем разных активах. Это не сравнение активов между собой, а проверка метода на прочность:

- **S&P 500** (традиционный фондовый индекс): кейс COVID-19, март 2020.
- **Bitcoin (BTC-USD)** (намного более волатильный крипто-актив): серия крипто-специфичных крахов: 2018 год, COVID-19 (март 2020), крах Terra/Luna (май 2022), крах биржи FTX (ноябрь 2022).

Ряды не привязаны к одному календарному периоду и не сравниваются друг с другом напрямую. По каждому активу берётся максимум доступной истории именно по нему. Если одна и та же модель одинаково чисто разделяет "спокойный" и "кризисный" режимы и на умеренно волатильном индексе, и на гораздо более волатильной криптовалюте, это довод в пользу того, что метод работает не только на одном конкретном ряду данных.

## Статус

В процессе, обновляется по ходу работы над дипломом.

- Блок 1: сбор данных и разведочный анализ (доходности, описательная статистика, стационарность, ARCH-эффекты)
- Блок 2: базовые модели (ARCH, GARCH, GJR-GARCH)
- Блок 3: марковские цепи и реализация Markov-Switching GARCH
- Блок 4: кейсы (S&P 500 / COVID, Bitcoin / крипто-крахи)
- Блок 5: сравнение моделей и VaR-бэктестинг
- Блок 6: текст работы и финальная сборка

## Данные

Дневные цены закрытия, скачаны вручную с Yahoo Finance (автоматическая загрузка кодом заблокирована в части рабочих окружений, поэтому данные скачиваются один раз и кэшируются локально). У каждого актива своя собственная максимальная доступная история, не общий период, подробнее выше.

Хранятся как CSV-файлы в `data/`:
- `data/sp500_prices.csv`
- `data/btc_prices.csv`

## Структура репозитория

Пока один ноутбук, анализ ещё строится. По мере того как код по каждому блоку стабилизируется, он будет расходиться по отдельным модулям и ноутбукам под каждый блок:

```
ms-garch/
├── README.md
├── README.ru.md
├── requirements.txt
├── data/
├── notebooks/          (план: отдельный ноутбук на каждый блок)
├── src/                (план: переиспользуемые функции, когда перестанут часто меняться)
└── vkr_msgarch.ipynb   (текущий рабочий ноутбук)
```

## Установка

```bash
pip install -r requirements.txt
```

Дальше открываешь `vkr_msgarch.ipynb` и запускаешь ячейки сверху вниз. Данные скачиваются один раз и кэшируются, при повторных запусках читаются из локальных CSV.
